# Supporto

*[English version below](#support)*

Questa pagina dice dove cercare aiuto, non ripete quanto già detto altrove: se stai cercando
come contribuire vai a [`CONTRIBUTING.md`](CONTRIBUTING.md), se stai segnalando una
vulnerabilità vai a [`SECURITY.md`](SECURITY.md) - **mai** con una issue pubblica.

## Prima di chiedere

**[Leggi la documentazione](https://fedcal.github.io/Telemedic/).** In particolare la
[guida dei fondamenti](https://fedcal.github.io/Telemedic/docs/10_fondamenti/00-come-usare-questa-guida)
per il contesto sanitario, gli standard e il regolatorio, e
[stato e limiti](https://fedcal.github.io/Telemedic/docs/00_overview/04-stato-e-limiti) per
sapere che cosa esiste oggi e che cosa no: il progetto è in fase di progettazione, senza
codice applicativo, e molte domande su «come si installa» o «come si usa in produzione»
trovano già risposta lì - la risposta, oggi, è che non è ancora possibile.

## Dove chiedere

| Hai bisogno di | Vai a |
|---|---|
| Una domanda d'uso, un chiarimento, un confronto | [Discussioni → Q&A](https://github.com/fedcal/Telemedic/discussions/categories/q-a) |
| Un'idea o un suggerimento non ancora strutturato come proposta | [Discussioni → Ideas](https://github.com/fedcal/Telemedic/discussions/categories/ideas) |
| Un difetto riproducibile | [Modello di segnalazione «Bug report»](https://github.com/fedcal/Telemedic/issues/new/choose) |
| Una proposta di funzionalità strutturata | [Modello «Feature request»](https://github.com/fedcal/Telemedic/issues/new/choose) |
| Il supporto per un sistema o uno standard esterno | [Modello «Integration request»](https://github.com/fedcal/Telemedic/issues/new/choose) |
| Una vulnerabilità di sicurezza | **Non una issue pubblica.** Segui [`SECURITY.md`](SECURITY.md) |
| Un dato reale pubblicato per errore | **Non una issue pubblica.** Segui [`SECURITY.md`](SECURITY.md): è un incidente |

## Che cosa aspettarsi

Il progetto ha oggi **un solo manutentore, a tempo parziale** (`GOVERNANCE.md`, «Stato
attuale»). Non c'è un impegno di tempo di risposta per le domande di supporto, a differenza
delle vulnerabilità di sicurezza, per cui `SECURITY.md` dichiara termini espliciti.

# Support

This page says where to look for help; it does not repeat what is already stated elsewhere:
for contributing see [`CONTRIBUTING.md`](CONTRIBUTING.md), for reporting a vulnerability see
[`SECURITY.md`](SECURITY.md) - **never** through a public issue.

## Before asking

**[Read the documentation](https://fedcal.github.io/Telemedic/en/).** In particular the
[foundations guide](https://fedcal.github.io/Telemedic/en/docs/10_fondamenti/00-come-usare-questa-guida)
for the healthcare context, the standards and the regulatory framework, and
[state and limits](https://fedcal.github.io/Telemedic/en/docs/00_overview/04-stato-e-limiti)
to know what exists today and what does not: the project is in the design phase, with no
application code, and many questions about «how do I install it» or «how do I run it in
production» already have an answer there - today, the answer is that it is not yet possible.

## Where to ask

| You need | Go to |
|---|---|
| A usage question, a clarification, a discussion | [Discussions → Q&A](https://github.com/fedcal/Telemedic/discussions/categories/q-a) |
| An idea or an unstructured suggestion | [Discussions → Ideas](https://github.com/fedcal/Telemedic/discussions/categories/ideas) |
| A reproducible defect | [«Bug report» template](https://github.com/fedcal/Telemedic/issues/new/choose) |
| A structured feature proposal | [«Feature request» template](https://github.com/fedcal/Telemedic/issues/new/choose) |
| Support for an external system or standard | [«Integration request» template](https://github.com/fedcal/Telemedic/issues/new/choose) |
| A security vulnerability | **Not a public issue.** Follow [`SECURITY.md`](SECURITY.md) |
| Real data published by mistake | **Not a public issue.** Follow [`SECURITY.md`](SECURITY.md): it is handled as an incident |

## What to expect

The project currently has **a single, part-time maintainer** (`GOVERNANCE.md`, «Current
state»). There is no committed response time for support questions, unlike security
vulnerabilities, for which `SECURITY.md` states explicit terms.
